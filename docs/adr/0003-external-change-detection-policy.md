# ADR 0003: 外部修改偵測採每請求 stat＋衝突橫幅，不自動 reload kea

kea 設定檔會由外部系統／人員直接編輯；kealight 若只看啟動時的快照，後續編輯會建立在已失效的基底上。我們決定以**每請求 `stat(mtime+size)`** 比對基準（比對到變化才重 parse）偵測外部修改：無未套用變更時**靜默重載**採用外部版；有未套用變更（`saves_since_apply > 0`）時**攔截 POST、顯示橫幅**讓使用者選「捨棄變更重新載入」或「以本系統覆寫」。採用外部版後 pending 歸零、套用鈕停用，但**不自動**對 kea 發 config-reload。

理由：這是低流量的內部管理工具，每請求一次 stat 是單一 syscall、零新依賴，比 inotify 的即時偵測簡單且無跨平台問題；橫幅政策確保使用者未套用的變更不能被外部修改悄悄銷毀（靜默覆寫只發生在沒有 pending 的時候）。不自動 reload 是因為外部系統對自己的修改負責，本工具只負責讓畫面與磁碟一致。代價是「有 pending 時新進 POST 被攔截」需要使用者多一步決策。
