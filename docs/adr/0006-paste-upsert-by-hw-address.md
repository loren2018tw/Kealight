# ADR 0006: 快貼以 hw-address 為覆寫鍵，與單筆新增的衝突拒絕並行

單筆新增／編輯時，hw-address 重複屬 Conflict 一律拒絕寫入；但「快貼」（Paste）設計成管理員從自備試算表一次匯入或更新目前 subnet 的 reservation，重複的 hw-address 正是拿來「更新既有筆」的訊號。我們決定快貼採用 upsert：以 hw-address 為鍵，與目前 subnet 內的既有筆相符就覆寫其 ip-address／hostname，不相符就新增；只有 IP 衝突等「非主鍵」規則才跳過該筆並附原因。

理由是：快貼的典型使用是拿外部維護的整份清單對齊伺服器設定，「重複即更新」是意圖而非錯誤，逐筆攔下會讓批次失去意義；而單筆新增的衝突拒絕仍保留，因為那是精確輸入、重複 MAC 幾乎都是筆誤。代價是誤覆寫風險——管理員貼錯清單可能整批改寫既有 IP／hostname——因此採用「先解析預覽、再一次寫回」的兩段流程，預覽逐筆標示新增／更新／無變化／跳過及原因。唯一性界線與既有衝突檢查一致，以 subnet 為界，跨 subnet 同名 MAC 仍視為新筆。

另有兩項沿用既有政策的取捨：整批以單一次寫回落地（單一備份、pending +1），且 commit 時重新解析原始文字、不信任預覽結果，以避免「預覽舊、套用新」的不一致。
