# ADR 0001: 寫回時整檔以標準 JSON 重寫，不保留註解

Kea 設定檔可含 `//` 與 `/* */` 註解，測試檔 `kea-dhcp4.conf` 以 3 空格縮排手工排版、4877 行、957 筆 reservation。我們決定寫回時做「整檔 parse → 修改 → 以標準 JSON 重新序列化」，不保留註解、也不保留原縮排風格。

理由是：保留註解需要手術刀式文字編輯或 JSONC 序列化器，兩者都顯著增加複雜度，而本專案的設定檔（見 testdata）本身不含註解，實際收益低。代價是設定檔會失去人工排版與註解——因此寫回前一律自動時間戳備份，且重寫時以固定縮排（3 空格，與現檔一致）輸出，讓 diff 盡量可讀。

由此衍生一條硬規則：**整檔重寫絕不能丟失任何未被建模的欄位**。因此序列化必須以 schema 無關的方式（保留原始 JSON 樹）進行，只針對 reservations 陣列套用型別化編輯。
