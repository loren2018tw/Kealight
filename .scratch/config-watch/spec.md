# 監看 kea 設定檔的外部修改

Status: ready-for-agent
Type: task

## 背景

kea 設定檔可能由外部系統／人員直接編輯。目前 kealight 只在啟動時載入一次，之後一律以記憶體模型為基底；外部修改不會反映，編輯可能覆蓋外部變更。

## 規範

1. **監看範圍**：僅 kea 設定檔。`kealight.toml` 的變動預期重啟生效，不監看。
2. **偵測機制**：每次請求（GET/POST 皆然）在取用模型前 `stat(mtime+size)`，與基準比對；有變化才重新 parse。基準在載入與自家寫回後更新（不得把自己寫回誤判為外部修改）。
3. **衝突政策**：
   - 無未套用變更（`saves_since_apply == 0`）→ 靜默重載，採用外部版。
   - 有未套用變更 → 橫幅二選一：「捨棄變更重新載入」（重載、pending 歸零）／「以本系統覆寫」（記憶體模型寫回磁碟、pending 不變）。
4. **POST 攔截**：有 pending 且偵測到外部修改時，編輯／新增／刪除／套用的 POST 一律攔截、回傳橫幅頁，決策後才繼續原意圖；無 pending 時先重載、再以新模型處理請求。
5. **pending 語意**：採用外部版的重載使 `saves_since_apply` 歸零、套用鈕停用；本系統不自動對 kea 發 config-reload（外部修改者自負）。
6. **檔案被刪除**：保留最後載入的模型、全頁警示「設定檔已被刪除」，仍允許編輯；寫回會重建檔案（備份步驟對不存在的檔案跳過）。
